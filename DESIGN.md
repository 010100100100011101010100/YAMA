# Yama frontend design

The current revision uses the user's selected Aceternity button style, Rare UI Folder in Files, and Rare UI Matrix Orb during comparison. The rest of the running UI retains BeautifulUI's original foundation and supplied component styling, with Yama colours in a separate file. The earlier boxy overrides are superseded. This is implemented for review, with no claim of visual approval. See `docs/design/action-components/README.md` for the new component mapping.

Inter is the Latin interface family, matching BeautifulUI's foundation; IBM Plex Sans Devanagari handles Hindi. Fonts are bundled locally with OFL notices. The source foundation uses 14 px body text; imported AI components retain their original 11.5–14 px labels and prose. Action buttons now use 14–16 px text and 44 px critical targets. Application-owned review instructions remain larger.

The desktop layout has a 224 px agent/tool rail, a full-height shared transcript, and a composer up to 848 px wide. The sidebar contains recent chats with human-controlled red unresolved and green resolved states, plus language and options. Notes, files and next steps sit in the transcript toolbar. Agent names and dithered portraits identify speakers within messages; there is no separate participant panel above the chat. The start view places a plain invitation and composer near the middle; ongoing conversations anchor the composer at the bottom. Chat and voice tabs use BeautifulUI's controlled ChatComposer header.

`src/app/beautifului/foundation.css` preserves the saved official foundation, except for repairing one malformed orphan gallery CSS fragment. `yama-colors.css` overrides colours only. The Tall prompt retains 22 px corners and 14 px padding; the chat window uses its original 14 px corners. Button uses Aceternity's vertical gradient, 8 px corners, inset ring and press feedback, with no magnetic pointer movement. The prompt control grid accommodates its 44 px icon buttons. Ten supplied BeautifulUI components remain in use, alongside TaskRows and ContextCards; the former LoadingState is replaced by Matrix Orb. AgentScreen remains saved for a future actual capture workflow. The unchanged BeautifulUI originals are in `docs/design/beautifului-supplied/`.

Voice mode centers the selected speaker and preview controls. It remains caption-only: no microphone permission, recording, synthesis, or model calls. At short phone sizes, the speaker and controls share a compact row; microphone-off information stays readable above the composer. The interrupted-state announcement remains available to assistive technology.

The transcript DOM and controlled draft persist across modes and agent selection. Reading earlier messages does not trigger a jump to new replies. Expanded work is inside the transcript scroller, keeping the composer accessible. Task state is application-controlled, with no timer-based success animations. Reduced motion disables decorative loaders, shimmer, portrait movement, and transitions while retaining the green speaking outline. Evidence and source controls are immediately available without delayed entrances. The prompt's `@` and `/` menus perform actual local actions; no placeholder integrations or fake dictation are shown.

Supporting panels retain native dialogs: modeless on desktop, modal at 1040 px and below. Opening focuses the heading; Escape/closing restores the opener. A different panel starts at the top; updates within it preserve reading position. Background work does not open a panel or take focus. The source-derived ApprovalCard requires explicit confirmation and retains focus on its confirmation control. Revision-bound confirmation, source provenance, corrections, exclusions, and handoff rules remain unchanged.

The animal animation described here was rejected by the user; further motion work is deferred. This pass leaves its implementation unchanged.

Saathi uses an eagle, Drishti a wolf, and Disha an elephant. To reduce the rejected coarse pixelation, the frontend uses the original finer generated portraits, copied unchanged to `public/agents/*-fine.png`, with smooth browser rendering. Their angular monochrome texture remains; the later coarse pixel pass is no longer displayed. The shared portrait component now renders a layered SVG illustration: wolf head yaw over its neck, an elephant trunk swing with an independently curling tip, and small eagle beak/feather movements. A slower 7.2 second float moves the illustration inside a steady green boundary and glow. This supersedes the uniform bob and tilt. The motion is a 2D illustration rig, not a 3D model or generated video. Source pixels are unchanged and no animation package is added. Voice preview uses its playing state; delivered text replies receive a brief 2.4 second presentation cue. Selection alone does not trigger it, and pause, stop, or voice handoff returns to the intact still portrait. Reduced motion disables all part and floating animations. This remains a caption preview, not live audio or phoneme-driven lip sync. Details are recorded in `docs/design/animal-motion/`. Previous birds and coarse studies remain historical artifacts. Manual screen-reader, physical mobile keyboard, reduced-motion browser emulation, and live audio review remain outstanding.

The 2026-10-14 finishing pass adds saved chat navigation, in-tab per-chat draft retention, manual resolve/reopen, agent nature information and state-driven typing dots. Actual handoff targets are retained in history and displayed in the shared conversation. See `docs/frontend-chat-finishing.md` for behaviour and limits.

The 2026-10-15 responsive pass keeps the chat sidebar vertical on desktop, with a 64 px collapsed icon rail. At 1040 px and below, navigation lives in a closed-by-default native modal drawer behind a 60 px app header. Chat selection, New chat, and Options dismiss the drawer; Escape and the backdrop also close it. Language settings stay inside navigation. The Chat/Voice controls and composer controls have 44 px touch targets, and tablet/phone messages and input use 16 px text. Demo badges, the fiction-only footer, connection-ready messages, saved-revision labels, empty-history guidance, and per-reply provider/revision captions are removed from the workspace. Errors, active progress, source provenance and older-reply context remain. See `docs/frontend-responsive.md`.

The composer retains its recipient selector and adjacent agent-nature information control. The selected recipient defaults to Saathi and does not follow automatic speaking-role changes. An @agent autocomplete uses the supplied PromptBar/GlideMenu row styling, with role descriptions and 44 px targets; the attachment and slash menus stay separate. Completion preserves caret position and following text. Plain-name requests show Saathi’s @target bridge before the specialist responds. See `docs/agent-addressing.md`.
